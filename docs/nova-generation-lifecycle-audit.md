# 小饕 APP / PC 生成交互检查

日期：2026-10-26。范围：Flutter 原生小饕、共用服务、后台协调器、本地缓存，以及 Go 后端生成接口的只读核对。

## 本轮已修改的问题

1. **恢复后的生成状态锁死**：恢复会话曾把 `_sending` 置为 true，而轮询又因 `_sending` 提前返回。恢复状态与本页面发出的请求分开；输入仍按整体生成状态限制重复发送。
2. **断线草稿冒充运行中的任务**：只有缓存正文不能证明服务器仍在生成。统一以当前会话的活跃请求、服务端状态判断；中断保留正文，显示中断标记及“重新生成”。
3. **后台过早清缓存或提前认定完成**：确认服务端状态前不删除草稿；离线不等于完成；仍在生成时不把部分正文当完整回答保存。
4. **切板块后流式进度不再保存**：草稿写入由 service 驱动，不再依赖旧页面 mounted；重进页面可继续从草稿接收进度，结束后查历史收敛。
5. **灯塔/任务结果随页面销毁丢失**：请求在 service 内保存最终结果与上下文，页面销毁后仍可完成本地保存；历史同步异步执行。
6. **并发缓存写入互相覆盖**：生成标记、草稿、历史共用 JSON 的读改写串行执行；删除最后一个键也真正落盘。
7. **切换会话污染另一会话**：活跃请求按 conversationId 归属；离开时固定会话 ID 和消息快照；历史加载及轮询校验页面请求版本。
8. **停止后旧回调覆盖新问题**：每轮发送及停止更新请求版本；底层流也校验自身版本，旧流不再覆盖新流的草稿、结果和生成标记。
9. **个人查询停止无效**：停止会释放查询忙状态并忽略迟到的进度；不触发任务写入。
10. **后台提醒误清与单会话轮询**：按会话保留未读完成提醒，支持多个会话分别轮询；停止一个会话不影响其他会话。
11. **退出重复写入**：后台、deactivate、dispose 复用离开保存过程，避免同一页面多次并发提交旧快照。
12. **重进附带问题重复发送**：预填问题只消费一次；有任务恢复中时保留为输入草稿，不自动触发停止。
13. **上下文及确认卡恢复**：灯塔结构化条件、图表、建议问题及未确认任务草稿一起保存；确认仍需用户点击。
14. **首屏恢复额外等待与频繁磁盘写入**：历史恢复不等待头像/模型目录；流式草稿写入节流，最终正文完整保存。

| 场景 | 处理方式 | 本轮验证 |
| --- | --- | --- |
| PC 切换软件后回来 | 保留本机活跃请求，旧历史不覆盖正在回复的气泡 | 代码路径与活跃请求测试 |
| APP 切其他板块后回来 | 共用 service 继续接收，恢复页面读取进度 | 缓存、流式、历史恢复测试 |

| 尚未收到第一个 token 就断线 | 不无限转圈，提供重试提示 | 恢复测试 |

| 同时存在多个后台会话 | 各自收敛，不相互停止或清未读 | 后台多会话测试 |
| 点击停止 | 不接受迟到的进度，释放本机忙状态，保留停止结果 | 个人查询取消测试、代码检查 |

| 灯塔回答后重进继续追问 | 保留查询条件与能力归属 | 持久化测试 |
| 任务预览退出再进 | 恢复未确认草稿，仍需明确确认 | 预览解析与持久化测试 |

## 仍需服务端完善的产品边界

1. 普通文本 `/ai/assistant/messages` 已在客户端断开后继续执行，并在服务端保存生成状态及回答。但多模态直连、个人查询的结果尚未统一纳入同一个持久任务模型。强制杀进程后不能保证所有类型完整续跑；客户端必须明确中断和重试，不能用本地缓存冒充后台运行。
2. 当前没有统一的服务端生成取消接口。本轮停止保证本机停止接收及迟到回调隔离，不代表所有远端推理计算都被取消。
3. 创建任务等写操作的“服务端已成功、客户端确认记录尚未落盘就被强杀”仍需由后端幂等请求号/执行回执彻底处理。恢复确认卡不自动执行写入。
4. 真机验收需分别检查 Android/iOS 的进程回收、断网重连、锁屏，以及 PC 最小化、切软件和休眠；桌面/手机宽度 widget 测试不能替代操作系统级验收。
