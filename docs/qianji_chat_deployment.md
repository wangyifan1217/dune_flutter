# 饕独立对话：接入与验证

新版饕使用 `qianji-go` 的 `/api/v1/qianji/chat`，会话和提问保存在 `qianji_chat_conversation`、`qianji_chat_turn`，不共用小饕历史。`qianji-go` 启动时自动运行迁移 V32 和 V33；部署前应按现有数据库备份和迁移流程检查。业务查询结果不存入历史，读取历史时以当前用户权限重新查询，因此数值可能与当时不同。

`DELETE /api/v1/qianji/chat/{id}` 删除当前用户自己的会话，数据库会级联删除其问答记录；不存在或不属于当前用户的会话返回 404。该接口使用 V32 已有的级联约束，无需新增迁移。

## 轻量模型配置

服务端默认复用已有 `TASK_BIND_LLM_BASE_URL` / `TASK_BIND_LLM_API_KEY` 或 `IM_SUMMARY_BASE_URL` / `IM_SUMMARY_API_KEY` 的 DeepSeek 兼容通道，默认模型为 `deepseek-v4-flash`。也可通过 `QIANJI_CHAT_LLM_BASE_URL`、`QIANJI_CHAT_LLM_API_KEY` 和 `QIANJI_CHAT_LLM_MODEL` 单独覆盖；配置独立地址时也必须单独配置对应密钥，避免把共享通道密钥发送到其他地址；显式设置空地址会禁用自动回退。部署脚本仅复用显式配置的摘要通道或 New API，不自动使用 Hermes 地址。意图解析只接收问题、当前日期及上一轮结构化意图。群响应的回答生成会额外向所配置的模型服务发送经当前用户权限及查询条件过滤后的原始记录（包含消息摘要、回复摘要和响应时间），不发送用户令牌；上线前应确认该模型通道可处理这些业务数据。其他板块目前仍使用模板回答。模型生成失败时群响应会明确提示 AI 不可用，不伪装为 AI 回答。不要将密钥写入代码或文档。

## 当前能力和边界

侧栏支持业务板块切换，历史和对话分页，旧版入口保留。新版支持各主要板块的有限统计，部分板块支持明细列表，资金借调支持按结清标记筛选，月结支持明确年月、应收应付及逾期查询；支持本月、上月、今年指定月份及有限的上下文追问。知识库、IM 会话、使用热力、工作情况、员工画像、差旅管理、会议纪要、研发账号、群响应、日报和任务支持按人员或部门查询；部门在当前用户可见结果内按名称过滤。任务负责人必须是当前用户本人或任务汇报线下属，统计按负责人 ID 精确过滤；同名人员分开显示。差旅的上游搜索也可能匹配部门，服务端再按姓名过滤；会议纪要按组织者或标题匹配，回答会标明匹配范围，且不支持按月筛选。日报支持单日筛选，不支持按月筛选；研发账号不支持按月筛选。

知识库和 IM 单次最多检查 200 条，使用热力最多 50 条，工作情况和员工画像的下游服务最多返回 200 人；会议纪要、研发账号、群响应和日报单次最多检查 100 条。可能截断时答案会提示结果不完整。资金流向、月结和资金借调不支持人员或部门筛选。无法准确识别的其他筛选条件会提示到原页面，不会忽略条件后返回全量结果。月度舆情、提案审核为样例页，已从新版查询范围中移除；未接入的具体查询会提示进入原页面。

追问“对应的明细”等说法会沿用上一轮的人员、部门、月份和状态。IM 会话和工作情况在人员唯一且结果未截断时调用对应人员明细接口，接口再次以当前用户身份校验范围；差旅显示已授权汇总返回的行程，员工画像显示已授权的模块摘要。日报、群响应和研发账号可列出监管接口返回的记录；提案时效直接列表不限定日期，统计后的明细沿用月份或默认近 30 天，最多检查 200 条并在可能截断时提示。我的任务、会议纪要、资金借调、资金流向和部分月结统计可追问对应列表。知识库新增监管文档接口：目标人员必须在监管范围内，查询他人文档时还必须已订阅对应知识库；因此明细可能少于监管汇总。个人文档库与监管汇总口径也可能不同。

部署时需先更新 `kb-go`，提供 `/api/v1/kb/supervise/documents`，再更新 `qianji-go`；新接口使用当前用户令牌，不要求数据库迁移。部署后应使用本人、范围内已订阅和未订阅人员、范围外人员四种身份验证明细权限与月份筛选。

在按人查询后，可以继续问“他的 IM 会话有哪些”等明确的跨板块追问；人员和已选月份会保留，目标板块不能按月查询时明确提示，不会悄悄忽略月份。模型无法使用时仍可通过规则处理这些问法。

群响应支持追问“列出全部”“按分钟显示”或组合使用；沿用上一轮的人员、部门和月份，按当前权限分页读取，最多检查 1000 条，未读完会提示结果可能不完整。分钟按秒数换算并保留两位小数，已回复记录不再显示误导性的“未回复 0 秒”。

对话结果中的结构化记录会显示最多 8 行预览，并提供 Excel 下载。用户提问中包含“Excel / 导出 / 下载 / 生成表格”时，如果结果含有结构化数据，客户端会自动生成文件；也可点击回答下方的“生成 Excel”。导出接口按会话和轮次定位查询，以当前用户身份重新执行并检查板块权限，不使用历史数据快照；单个工作簿最多写入 2000 行，超出时导出前 2000 行。没有结构化查询数据的回答不提供导出入口。

服务端以用户身份调用既有只读服务，资金流向和月结还会同时检查原始授权和用户当前有效权限；资金借调由原服务按用户当前有效权限校验。历史结果按当前权限重查，权限无法确认时隐藏历史问题。普通查询失败、超时和权限拒绝应分别提示；不支持修改、审批等写操作。

## 发布前验证

1. 在测试环境应用 V32、V33，确认新旧客户端与原有饕页面可用；配置轻量模型后检查模型仅收到问题和上一轮结构化意图，不包含业务查询结果。
2. 用两个账号验证新建会话、跨设备读取、超过一页的历史以及跨账号访问被拒绝。对同一账号撤销饕或各业务板块权限后，验证历史重读和新查询不暴露失权数据。
3. 覆盖各板块的快捷问题、指定年月、列表、支持的追问、未支持条件和原页面入口；模拟下游 403、超时、不可用以及账号切换。
4. 用 APP 和宽屏分别验证侧栏展开、收起、新旧切换以及离开页面后重新校验。模型未配置、失败或超时情况下验证规则回退。

本地 `go test ./...` 与 Flutter 页面测试属于代码级验证，不能替代真实数据库、权限服务、模型和客户端的端到端联调。
