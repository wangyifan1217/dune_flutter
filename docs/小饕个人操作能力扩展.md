# 小饕个人操作能力扩展

更新时间：2026-10-16（Asia/Shanghai）

项目：`D:\workspace\new_dune_web\flutter`

状态：需求说明，尚未开工。浮窗外观问题本轮不改。

## 1. 要做成什么

小饕要能替当前登录用户，完成沙丘上跟这个人相关的操作。用户用一句话交代，小饕在本人权限内把事做完，并把结果说清楚。

第一批例子：

- IM：找人、打开或建立私聊、发送文字、把一条消息或小饕的回复转发到指定会话
- 任务：查看我的任务、创建任务、补截止时间和负责人、改我能改的状态

后面按同一套规则扩展到会议、审批、日报、收藏等个人事务。组织管理、后台配置、别人的数据不在范围内。

## 2. 现在已经有的，和还没有的

| 能力 | 现状 |
| --- | --- |
| 全局浮窗里跟小饕说话 | 已有。对话走现有 `NativeNovaService`，只返回文字 |
| 主动提一句临期任务或页面帮助 | 已有。任务只读，点进去才打开任务详情 |
| 完整小饕页把回复转发到 IM | 已有，入口在完整页，不在浮窗。见 `native_nova_page.dart` 的 `_forwardAssistantReply` |
| 会议纪要数字员工查纪要、完成行动项 | 已有，但是另一条数字员工链路，不在小饕浮窗里 |
| 浮窗里直接发 IM、转发原消息、创建任务 | 没有 |
| 小饕按一句话选择并执行沙丘个人操作 | 没有 |

浮窗、桌面独立小窗、点空白收起，属于陪伴展示，不在这份能力扩展里继续改。

## 3. 身份和确认

操作的人永远是当前登录用户。模型不能指定 `userId`、`scope`、`assignee` 去冒充别人。找同事、指定任务负责人时，先按姓名在当前用户可见的通讯录里解析，解析不到就问，不猜一个 ID。

读操作可以直接做：查我的会话、查我的任务、查未读。

写操作先告诉用户将要做什么，等人确认再执行：

- 发给谁、发什么
- 转发哪条消息、转到哪个会话
- 任务标题、负责人、截止时间

用户说「取消」或关掉确认，就不调用接口。执行失败时，用现有友好错误文案说明，不假装已经成功。

群管理（拉人、踢人、解散）、删除任务、撤回消息，比普通发送更重，单独确认，不跟「发一句话」放在同一档。

## 4. 个人操作范围

只覆盖当前用户在沙丘客户端里本来就能做的事。

### 4.1 IM

现有客户端能力在 `ConversationService`。

| 用户可以说 | 要做的事 |
| --- | --- |
| 给某人发一句 | 解析同事，找到或建立私聊，发送文字 |
| 把这条消息转发给某人 / 某个群 | 转发指定消息，而不是只转发小饕自己的回复 |
| 把小饕刚才的话发到某个会话 | 沿用现有「转发到 IM」 |
| 我跟某人最近说了什么 | 读取该私聊的近期消息 |
| 有哪些未读 | 读取会话列表和未读数 |

发送图片、文件、语音可以后做。先打通文字和转发。

### 4.2 任务

现有客户端能力在 `TaskApi`。浮窗今天只会列出临期任务。

| 用户可以说 | 要做的事 |
| --- | --- |
| 帮我建一个任务 | `createMain`，标题必填；负责人、截止时间能解析就带上 |
| 我今天 / 这周有哪些任务 | `listTasks(scope: mine)` |
| 把这个任务标成进行中 / 完成 | 仅当当前用户有权修改时 `patchTask` |
| 把任务转给某个同事 | `assignTask`，负责人必须解析成功 |

考核、HRBP 总览、团队日报监管不属于个人操作。

### 4.3 下一步再接的个人事务

这些客户端或数字员工里已经有对应能力，小饕尚未统一调用：

- 会议：我的会议、纪要、我的行动项。完成行动项沿用数字员工「先确认再写」
- 审批：待我处理、我发起的、催办。解释和催办草稿已有 approval assistant 接口
- 日报：查看、提交我自己的日报
- 收藏：收藏一条消息、查看我的收藏
- 状态：查看或修改我的 IM 在线状态

知识库、灯塔、提案时效是业务查阅，不是「替我办一件个人的事」，不放进第一批。

### 4.4 IM 上还能代办的

`ConversationService` 里除了发文字和转发，这些也是本人会话上的操作：

| 用户可以说 | 要做的事 |
| --- | --- |
| 回复他刚才那句 | 引用回复，而不是另起一条无上下文的消息 |
| 撤回我刚发的那条 | `recallMessage`，只撤回本人发出的 |
| 这个会话标已读 / 先别提醒我 | 标已读，或改我自己的会话设置（免打扰） |
| 把这条钉住 | 置顶或取消置顶 |
| 我之前跟他说过合同的那句 | 在我的会话里搜消息 |
| 帮我自己记一条 | 发到现有的「给自己」备忘会话 |

图片、文件、语音后做。聊天文件存到微盘、微盘文件发到会话，可以跟第 4.8 节一起做。

### 4.5 任务上还能代办的

| 用户可以说 | 要做的事 |
| --- | --- |
| 给这个任务补一句进度 | 写进度，不改考核和评价 |
| 下面再拆一个子任务 | `createSubtask` |
| 把这个任务发到群里 | 沿用现有任务分享到 IM |
| 这个指派我接了 / 先不接 | 只处理发给当前用户的指派 |

评价、删除、考核规则不放进日常代办。

### 4.6 日程和会议

客户端已有创建会议，会议数字员工已有「我的会议 / 纪要 / 行动项」。

| 用户可以说 | 要做的事 |
| --- | --- |
| 我今天有哪些会 | 只读列出本人相关会议 |
| 约明天下午和某人开会 | 时间、参会人确认后再创建 |
| 上次会的行动项做完了 | 确认后完成行动项 |
| 把这条行动项变成任务 | 先读行动项，再走创建任务 |

### 4.7 审批里只属于我的

只处理当前用户自己的待办、自己发起的单据、自己的草稿。

| 用户可以说 | 要做的事 |
| --- | --- |
| 还有几条等我批 | 只读待办数量和标题 |
| 我发起的到哪了 | 只读进度 |
| 催一下这单 | 沿用现有催办，发送前确认 |
| 继续填昨天那个草稿 | 打开对应草稿，不替用户直接提交 |

同意、驳回、付款、用印不跟「发一句话」放在一档。即使用户说「同意」，也要打开原审批页，由用户自己点。

### 4.8 通知、文件和我自己的情况

| 用户可以说 | 要做的事 |
| --- | --- |
| 有什么新通知 | 读通知中心，按条摘要 |
| 通知都看过了 | 全部标已读，先确认 |
| 我微盘里那个文件在哪 | 在本人可见的微盘里查找 |
| 把这个文件发到群里 | 确认目标和文件后再发 |
| 我这周在忙什么 | 只读工作节奏、我的任务和会议，口头汇总 |

工作画像只读。不改绩效、不改考核、不提交别人的日报。

### 4.9 一句话串起来

单点操作打通之后，小饕的价值在跨域，而不是每个按钮各说一遍。这些都由前面的只读工具查出对象，再对写操作逐项确认：

- 把刚才这段聊天记成任务，并告诉负责人
- 把某条未读里提到的事建成任务
- 会前把纪要里的行动项转成任务，并通知负责人
- 早间简报：未读、今天的任务、今天的会，有需要处理的再问要不要办

早间简报是主动说的，沿用现在浮窗的频控：不在输入、通话、录音时打断。

### 4.10 先不要一句话做完

这些即使用户说得很明确，也只打开原来的页面，或先列出摘要：

- 同意或驳回审批
- 付款、报销、用印、薪酬
- 解散群、删除任务、清空聊天记录
- 修改组织、权限、后台配置

## 5. 建议做法

不要在浮窗里各写一套如果这句话包含「转发」就调接口。会议数字员工已经验证过一条路：模型看到工具列表，决定调哪一个；写操作由界面确认；真正的请求用当前登录会话发出。

小饕个人操作建议收成一组工具，挂在现有对话上，而不是再做一个新的聊天后端：

1. 只读：列会话、读近期消息、列我的任务、搜同事
2. 写：发文字、转发消息、创建任务、改我能改的任务
3. 浮窗和完整页共用这一组。浮窗负责短确认；完整页可以展开选人和改字段
4. 工具参数里不出现当前用户 ID。会话 ID、任务 ID、对方用户 ID 来自前一步只读工具的结果

`docs/DUNES-MCP运行时方案.md` 里的委托令牌和按域拆工具，仍然是服务端边界。个人 IM 和任务如果走 MCP，也要单独的域，不能跟会议纪要工具混在一个列表里。客户端在服务端工具就绪前，可以先用现有 `ConversationService` 和 `TaskApi` 把确认和调用跑通。

## 6. 建议顺序

1. 发私聊文字，带确认
2. 转发一条已有 IM 消息，或转发小饕刚说的话
3. 创建任务，带确认
4. 查询我的任务、我的未读，不需要确认
5. 引用回复、撤回自己的消息、标已读
6. 任务进度、子任务、把任务分享到会话
7. 今日会议、早间简报（未读 + 任务 + 会议）
8. 会议行动项、审批催办、个人日报、通知标已读
9. 跨域：聊天记成任务、行动项转任务并通知负责人

每一步都要能在 Windows 客户端和手机 App 上用同一套确认。桌面独立小窗只是另一个展示面，不单独做一套操作。第 4.10 节里的操作不排进这个顺序。

## 7. 不做

- 不替别人发消息、建任务、审批
- 不读取当前页面里用户没打开的正文，然后声称已经看过
- 不把组织配置、权限配置、提案时效查询算进个人操作
- 不把第 4.10 节的高风险操作做成一句话提交
- 本文件不包含浮窗拖出桌面后的外观修改
