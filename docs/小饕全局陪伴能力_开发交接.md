## 4. 接入架构

```text
DunesShell
  ├─ NovaPresenceHandle：让主壳返回操作先收起面板
  └─ NovaPresenceHost
       └─ NovaPresenceScope（InheritedWidget，向后代提供 open）
            └─ Stack
                 ├─ 原有 NativeScreenHost 和边缘返回手势
                 ├─ 小饕轻提示气泡 / 空闲头像
                 ├─ 面板展开时的轻遮罩
                 └─ NovaPresencePanel
```

### 主壳

- `DunesShell` 用 `NovaPresenceHost` 包裹原有页面 Stack。
- 使用 `ObjectKey(widget.session)`，会话对象变化时重新建立宿主，避免旧账号提示状态泄漏。
- `NovaPresenceHandle.closeIfOpen` 返回是否消费了关闭操作。
- 主壳 `PopScope` 优先调用该方法，再执行原导航返回。

### 原有入口

`DunesMainTabBar._buildAiButton` 中的回调顺序为：

1. `widget.onOpenAi`；
2. `NovaPresenceScope.maybeOf(context)?.open`；
3. 原来的 `navigation.go('C4')`。

Windows 竖栏原本没有同一个移动端头像按钮；桌面主要依靠新增的全局悬浮头像/气泡入口。通讯列表原有顶部小饕入口仍可进入完整页面，本次没有统一替换所有旧入口。

### 页面范围

默认开放：`C1`、`B2`、`QJ`、`LH`、`LM`、`QJA`、`K1`、`K3`、`MM-L`。

原生 Windows/macOS 额外开放桌面通讯页面 `C2`（群聊）、`C5`（私聊），同时将 `C1/C2/C5` 识别为桌面聊天场景。

这里使用现有 `isDesktopCommOnly` 判断原生桌面，不等同于浏览器宽度。宽屏浏览器可以使用桌面面板布局，但不会自动拥有原生桌面私聊/群聊的开放范围。

外部用户不显示。表单、嵌入式业务系统、其他 AI 页面、通话等未在白名单里的页面不显示。

`C1/C2/C5` 的页面名称明确映射为“消息/群聊/私聊”，避免引用生成路由注册表中带示例人名的页面标题。

## 5. 主动提示的实际数据与触发

### 5.1 真实临期任务

在主页面或桌面聊天场景，且账号拥有 `taskPendingAccess` 时调用现有：

```dart
TaskApi(session).listTasks(
  scope: 'mine',
  size: 100,
  maxPages: 3,
  dateFrom: 今天零点,
  dateTo: 明天零点,
)
```

- 请求超时为 12 秒；失败不弹错误通知。
- 任务拉取最多每 5 分钟一次，且由页面停留/导航等触发，不是常驻后台轮询。
- 前端再次筛选 `ownerUserId == 当前用户`。
- 仅接受 `active` 或 `in_progress`。
- 截止时间转换到本地时间，范围是今天零点至后天零点，不包含后天。
- 按截止时间排序，只选择第一条候选任务。
- 文案示例：“「任务名称」今天到期，要一起梳理一下吗？”
- 模型中保留真实任务对象，可直接打开 `NativeTaskDetailView`。
- 提供给 AI 的任务上下文含名称、说明、进度、截止时间；没有额外读取子任务或任务明细。

### 5.2 页面帮助建议

- `K1/K3`：提供整理资料/提炼重点的帮助建议。
- `MM-L`：提供整理会议行动项的帮助建议。
- 桌面 `C1/C2/C5` 没有临期任务时：提供“我在这里。想整理思路或讨论下一步，随时叫我。”的固定陪伴提示。

这些文案属于帮助邀请，不表示已读取当前文档、会议正文或聊天内容。

目前没有接入审批停留时长、审批节点异常、会议生成完成、行动项新增等真实业务事件。

### 5.3 频率与避让

- 初始化、导航变化、返回前台、输入焦点变化等情况后，等待 6 秒再评估。
- 两次主动展示至少间隔 15 分钟。
- 同一个提示 ID 在内存中只展示一次；持久化记录限制 24 小时内重复展示。
- 气泡展示 14 秒后自动收起；打开面板后停止自动收起。
- 支持关闭单条提示，以及“24 小时内不主动提示”。
- 录音进行中、应用不在前台、软键盘打开、输入控件获得焦点、面板已展开、其他路由覆盖等情况会暂缓主动展示。
- 导航变化会关闭面板和当前提示。
- 应用切回前台时会更新界面状态并重新评估，最后一次 Windows 构建包含此修正。

持久化存储使用 `SharedPreferences`，前缀：

```text
nova_presence_<URI编码后的apiBase>_<userId>
```

后缀包括 `.last`、`.quiet`、`.seen.<messageId>`。

## 7. 原地对话的接口接法

`NovaPresencePanel` 创建独立 `http.Client` 和 `NativeNovaService`。

首次发送：

1. `createFreshConversation()` 创建独立会话；
2. 构造首条上下文；
3. 调用 `sendAndReply(conversationId, text)`；
4. 展示 Markdown 回答。

有真实任务时使用该任务的上下文。其他场景只传页面名称，并明确告知模型“没有页面内容”，不要推测当前聊天或文档内容。

当前使用非流式 `sendAndReply`，等待时显示“让我想一想…”。错误通过 `friendlyErrorText` 展示，提供重试。发送期间防止重复发送。

关闭面板时会释放 HTTP client、输入控制器和滚动控制器。会话持久化依赖原有 `NativeNovaService`，并非本次另建存储系统。

## 11. 已知限制与建议优先复核事项

以下是代码边界或待验证点，不代表都已确认为运行故障。

1. **主动内容仍很有限。** 只有临期任务、固定页面帮助邀请和桌面陪伴提示。没有审批超时、会议完成等事件订阅；没有系统级后台守护或服务端调度。
2. **没有完整业务上下文。** 私聊/群聊面板不知道当前聊天正文或联系人；文档/会议页也没有自动注入正文。当前只传页面类型或真实任务基本字段。
3. **输入避让偏保守。** `_editing` 判断输入控件是否有焦点，不是判断实际键入；桌面聊天自动聚焦空输入框时也可能一直暂缓主动提示。若用户说气泡不出现，应优先检查此处。
4. **主动提示不是定期轮询。** 6 秒评估由导航、前后台等事件触发。长时间停在同一页面不会每隔 5 分钟自动刷新任务。5 分钟是请求限频，不是刷新周期。
5. **每次只选最早一条候选任务。** 若这条已展示，会直接返回，没有继续选择次早候选；没有合并多个任务的策略。
6. **任务日期/分页依赖后端语义。** 前端按今天与明天筛选，但后端 `dateFrom/dateTo` 的含义和边界仍应线上核实。最多取 300 条，且只接受本人 owner，不包含仅作为参与人或共同负责人的任务。
7. **任务缓存可能短时过期。** 任务完成后若没有重新取数，已有 `_dueTask` 不一定立即失效。
8. **桌面避让高度硬编码。** `244` 只覆盖当前常见聊天输入区尺寸；用户调整输入区高度、窗口缩放/DPI 时需要实机检查，后续最好读取真实输入区边界。
9. **不是所有路由都能覆盖。** 宿主位于主壳内，使用独立 Navigator route 打开的页面可能盖住它；对话框、搜索浮层、详情子路由需进一步核对。不要宣称支持所有 App 页面。
10. **关闭面板会销毁当前面板状态。** 局部 `_turns` 和会话 ID 不保存在宿主，重新打开不会自动恢复上一次面板；后台请求可能因 client 关闭而中断。历史是否完整应结合原有服务验证。
11. **非流式对话。** 没有逐字输出、停止生成、附件输入和语音输入。等待过程只有状态提示。
12. **重试与历史需要复核。** 重试会再次调用发送服务，前端不重复插入本地显示的 user turn，但服务端历史是否重复、请求是否具备幂等性没有端到端测试。
13. **展开页没有接齐全部外部导航回调。** `_expand` 创建 `NativeNovaPage` 时传入 session、会话 ID、返回回调，没有传知识库/会议/数字员工等宿主回调，完整页相关跳转需复核。
14. **频控会让演示时看不到气泡。** 15 分钟冷却、24 小时已展示记录、内存 `_seen` 和免打扰均影响展示。调试时只处理当前账号对应的 `nova_presence_...` 键，不要清空整个 App 设置。
15. **提示展示即记为已展示。** 没有区分用户真正阅读、点击或忽略；也没有提示反馈/效果指标。
16. **宿主状态与架构还可整理。** `DunesMainTabBar` 直接 import 了包含业务页面依赖的 host 文件；可考虑将 `NovaPresenceScope/Handle` 拆成轻量文件。`ObjectKey(session)` 会在 session 对象被替换时重建包含原页面的子树，需核对会话资料刷新时的影响。
