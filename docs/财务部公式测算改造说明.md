# 销售提案 · 财务部改为按公式测算（2026-10-11）

入口：工作台 → 业务与财务 → 提案填报 → 销售提案（B2SALES）。

## 改了什么

- **删除「电子券采购成本」**（`couponProcurementCost`）：表单字段、复核键、填报完整度、顶部年化测算、增值税进项都不再使用。
- **财务部不再手填金额**，改为「测算」三段，从上往下就是利润瀑布：
  1. **收入**：下拉选渠道侧结算公式（资管 `/out/shaqiu/catalog/formula`，`productSource=CHANNEL`），按产品业务平台只列对应那一组：
     - 运营商：CX_BENEFIT、CX_CARD_DATA、CX_MEMBER
     - 能源：DIGITALG、MY
     - 积分返费 / 星和动力 / 移动运营商：POINTS_REBATE、POWER_PACKET、POWER_COUPON、POWER_MEMBER、YD
     - 同组同一公式编码只留一条。默认取产品销售结算里已选的公式。
  2. **成本**：项目 / 业务 / 经营 / 税务四类，每类多选成本项（弹窗勾选），每项再选计算公式，金额自动算。
  3. **利润** = 收入 − 项目成本 − 业务成本 − 经营成本 − 税务成本；毛利率 = 利润 ÷ 销售规模。
- **推广费**：阶梯计费，规则待设计。当前可选但按 0 计，页面标「阶梯 · 设计中」。

## 页面结构（10-11 第二版）

财务部分三块：**产品结算** → **成本** → **利润**。

- **产品结算**：结算条款、供给侧 / 渠道侧、结算账户。比例、票种、税率只在这里出现。
- **成本**（hero 样式块）：顶部大数字年化成本 + 占规模 + 四类构成条；下面一行一项：项目 / 业务 / 经营 / 税务成本、周转资金。公式、代入、可改的选择都收在每行的展开里。
- **利润**（hero 样式块）：顶部年化利润 + 毛利率 + 「收入 − 成本」；下面收入（选收入公式）、利润、毛利率三行。
- 顶部年化测算 hero 联动：「成本 / 利润」区块标题、hero 里的算式、各小格点一下跳到下方对应块，并自动展开对应那一行。锚点：`financeCost`、`financeProfit`、`revenue`、`profit`、`margin`、`costItems`、`businessCost`、`operatingCost`、`taxCost`、`turnoverTimes`。

### 项目成本不再重复选公式

- 产品结算里有「应付 · X」的项目成本：自动计入成本，标「产品结算」，不能删、不能换公式，只写出处（如「取自产品结算 · 应付 · 机构返佣 比例 0.01」）和代入。
- 原来的「收入 × 成本结算比例」选项已删除（与合同「按规模 × 比例」口径不一致）。
- 产品结算里没有的项目成本（推广费、券使用成本等）才在成本块里补选；非阶梯项会提示「请在产品结算补一行应付」，按 0 计。

## 后端（flow-go）

  - `GET /api/v1/proposal-intakes/finance-formulas` 返回公式字典；
  - `GET /api/v1/proposal-intakes/options` 的 `finance.formulaCatalog` 里带同一份字典（页面打开即有）；
  - 资管公式缓存 10 分钟；资管不可达时用 2026-10-11 快照兜底（`source=fallback`）。
  - 四类成本项和公式先写死在后端（`proposalDefaultCostCategories`），项目成本会并入资管 / 管理端配置的名称，业务成本以资管 BUSINESS_COST 为准。
- 复核字段去掉 `couponProcurementCost`；负责人二可回写公式选择字段；业务成本加密时，负责人二回写的利润 / 毛利率不覆盖已存值，读取时也隐藏（利润含业务成本）。
- 市场部负责人一单独保存业务成本时，连同利润、毛利率、税务成本一起写回。

### 公式 kind（前端按 kind 计算）

| kind | 算法 |
|---|---|
| EXPRESSION | 收入：资管表达式代入。业务量类变量（销售、核销、现金、券包销售款…）取年化规模；结算比例 = 产品结算算出的收入 ÷ 年化规模；退款按 0；推广费 / 机构返佣 / 平台服务费 / 支付手续费 / 渠道侧N 等取产品成本结算匹配值；取不到的变量按 0 并在页面提示。单价类公式直接用产品结算（单价 ÷ 面值）算出的收入。 |
| SETTLE_SCALE | Σ 关联产品年化规模 × 成本结算比例（原「从产品成本结算匹配」） |
| SETTLE_REVENUE | 收入 × 成本结算比例 |
| SCALE_RATE / REVENUE_RATE | 销售规模 × rate / 收入 × rate |
| GROSS_RATE | (收入 − 项目成本) × rate |
| NET_OP_RATE | (收入 − 项目成本 − 经营成本) × rate |
| PRETAX_RATE | (收入 − 项目 − 业务 − 经营) × rate |
| VAT | (销项 − 进项) × 1.12，进项只算项目成本 |
| TIERED | 阶梯（设计中），按 0 计 |

### 推广费阶梯

- 数据：`promotionTiers = {basis: monthly|annual, mode: whole|excess, tiers: [{from: 万元, rate: %}]}`，存在产品财务组里（主 / 子各一份），负责人二可改，复核跟随「项目成本」。
- 计量：按月规模（年化 ÷ 12 分档，月费 × 12）或按年规模。
- 计费：全额累进（落在哪档整笔按该档比例）；超额累进（每段按各自档位比例再加总）。
- 优先级：配了阶梯按阶梯；没配但产品结算里有「应付 · 推广费」按产品结算；都没有按 0 计并标「阶梯 · 未配置」。
- 与资管接口的关系：资管结算方式字典里 `settleMethod=3` 为「按阶梯价格」，结算行只带 `thresholdAmount`（单一门槛），没有档位明细，所以档位在提案里配置；推广费应付行的结算方式选「按阶梯价格」时以提案档位为准。
- 页面：成本 → 项目成本 → 推广费，展开后是计量 / 计费切换和档位表（起点、比例、删除、添加档位），命中档位高亮，下面写代入过程。

## 第八版：按产品选公式（10-12）

### 规则
- 收入、项目成本、业务成本、税务成本**按产品**选公式：主产品、子产品各自一条，编号显示为「1、xxx产品」，展开后分「收入 / 项目成本 / 业务成本 / 税务成本」四段。
- 经营成本**整单只选类型**（差旅成本、招待费），不选公式、不计金额、不进利润。
- 利润 = 收入 − 项目成本 − 业务成本 − 税务成本；业务成本公式改为「（收入 − 项目成本）× 10% / 45%」，所得税改为「（收入 − 项目 − 业务）× 25% / 15%」。
- 业务成本仍由市场部负责人一按产品选择，负责人二不可见。
- 周转资金、月周转次数不变：填写人填月周转次数，周转资金 = 年化规模 ÷ 12 ÷ 月周转次数。
- 推广费：某个产品选了推广费，可新增多套阶梯方案（每套有名称、按月 / 按年、全额 / 超额、档位），各套金额相加。

### 数据
- 新字段 `form.productFormulas = { skuId: { owner, revenueFormula, revenueFormulaGroup, financeFormulaTouched, promotionPlans, costItems, costItemFormulas, businessCostItems, businessCostItemFormulas, taxCostItems, taxCostItemFormulas } }`，`owner` 为 `main` / `children`。
- `promotionPlans = [{id, name, basis, mode, tiers}]`。
- 老数据：产品条目缺的字段沿用所在组（`productFinance.main` / `children`、顶层）的旧选择；旧的单套 `promotionTiers` 视为「方案1」。每次测算、保存前补全所有产品条目（`proposalMaterializeProductFormulas`），已删除产品的条目清掉。
- 测算：每个产品单独算（只带这个产品的结算；规模用产品自己的，没有的平分组规模剩下的部分；同一销售结算组里其他产品上的应付行同样生效），再加总写回组上和顶层的 `revenue`、`costItems`、`projectCost`、`taxCost`、`profit` 等合计字段。开关关掉时这些金额不展示，打开后列表和顶部 hero 照旧读合计。
- 经营成本只存 `operatingCostItems`，`operatingCostItemAmounts = {}`、`operatingCost = 0`，不再存 `operatingCostItemFormulas`。

### 页面
- 开关 `kProposalFinanceShowEstimates`（当前 `false`）：财务部只显示每个产品的收入公式和成本公式，所有测算金额、代入过程、利润块先屏蔽；块名改为「收入与成本公式」。打开开关即恢复金额显示。
- 同一开关关掉时，详情顶部不再展示收入、成本、利润、毛利率、售价和「规模 → 收入 → 利润」柱；只留产品、渠道、任务评级、年化规模、月均规模、周转资金、SKU。项目概况里的年化成本 / 年化利润卡、链路里的财务金额、列表「计划毛利率」一并先不展示。经营成本本来就不计金额。

### 复核
- 逐条复核项：`sku:<skuId>:revenue`、`sku:<skuId>:costItems`（含推广费方案）、`sku:<skuId>:taxCost`，每个产品各三条；业务成本不逐条复核，随财务整板块锁定。
- 不再要求逐条复核 `revenue`、`profit`、`margin`、`costItems`、`taxCost`（这些字段仍按原规则锁定）。

### 后端（flow-go）
- `proposalIntakeMergeProductFormulas`：按产品、按字段合并，哪个产品哪一类复核过就保留库里的值；`financeCompleted` 后整份锁定。
- 业务成本加密 / 保留 / 补丁覆盖 `productFormulas` 里的 `businessCostItems`、`businessCostItemFormulas`：负责人二看不到、改不了；市场部负责人一保存时只换这两个字段。
- `proposalIntakeReviewTarget` 接受 `financeItem:sku:<skuId>:<kind>`，指派给财务部负责人二；`proposalIntakeFinanceReviewItemKeys` 按可售产品生成必需项。
- 公式字典：经营成本项不带公式，推广费标 `multiPlan`，业务成本、所得税表达式去掉经营成本。
